# 撞车检测（Collision Check）

## 这个 skill 存在的唯一原因

用户有过一次真实的误杀：做完方案后做撞车检查，看到两篇相隔一天发布的论文，判断"完全撞车"，说了句"算了"。后来逐字读完正文才发现——**不是同一个东西，有三处实质性区别**。

所以这个 skill 的第一原则是：

> **禁止输出「撞车 / 没撞车」的二值结论。**
> 任何"有人做过"的判断，都必须附带"**他们做了什么**"和"**他们没做什么**"。

**"他们没做什么"才是产出。** 它是用户差异化空间的来源。

## 什么时候触发

满足任意一条就应该跑：

- 用户提出一个新的研究方向、选题、课题
- 用户说"这个想法有没有人做过""查一下撞车""看看有没有人做过类似的"
- 用户准备开题、写 proposal、写研究计划
- 用户在做选题决策，需要判断"值不值得投入"
- **用户说"算了，这个方向有人做过了"** ← 这一条最重要，必须立刻跑一次再让他决定

最后一条是硬性的：**当用户想放弃一个方向时，不要附和他的判断，先跑一次撞车检查。**

## 执行流程

### 第 0 步：确认输入

需要一段方向描述，包含：问题、方法、预期贡献、约束条件。如果用户只给了一句话，先补全再跑——**方向描述越具体，检索质量越高**。

### 第 1 步：跑脚本

```bash
python scripts/collision_agent.py --idea "<方向描述>"
python scripts/collision_agent.py --file <方向文件> --since 2023
```

环境变量：

| 变量 | 说明 |
|---|---|
| `OPENAI_API_KEY` | 必填，否则退化为只检索模式 |
| `OPENAI_BASE_URL` | 可选，兼容任何 OpenAI 协议端点 |
| `COLLISION_MODEL` | 可选，默认 `gpt-4o-mini` |
| `OPENALEX_MAILTO` | 可选，进 OpenAlex polite pool |

**如果用户没有配置 API key**，改用只检索模式，并且**必须手写英文检索式**：

```bash
python scripts/collision_agent.py --idea "..." --no-llm \
  --query "english query 1" --query "english query 2"
```

原因见下方「已知限制」第 1 条。

### 第 2 步：检查报告质量

脚本产出 `reports/CC-*.md`。**不要直接把报告丢给用户**，先自己看一遍：

- 检索结果里有没有明显不相关的噪声？有的话，换检索式重跑；
- 三栏判定里有没有"证据不足"？有的话，那一条需要人工补检索；
- `已被占据` 的条目里，有没有只凭标题相似就下的判断？**这是误杀的高发区。**

### 第 3 步：遇到「部分重叠」或判断不确定时，升级到深读

脚本只能看摘要。**如果结论是"部分重叠"，或者用户倾向于放弃**，就必须读正文——这一步是可选但强烈建议的：

派一个子代理去读那几篇论文的**方法部分**，回答三个问题：

1. 它的核心机制具体是什么？（不是它声称做了什么，是它实际怎么做的）
2. 和用户方案相比，机制层面的差异有哪几处？
3. 它明确**没做**什么？

判断标准见 `references/criteria.md`。

### 第 4 步：回填想法日志

报告末尾有一行可直接粘贴的表格行。如果用户有想法日志，**主动提醒他填**，尤其是这两列：

- `检查结论`：`真撞车` / `看起来像` / `没查到` —— **不要把"部分重叠"归成"真撞车"**
- `回访日期`：决定日 + 90 天

模板见仓库的 `templates/idea-log.md`。

**这一步不是可选的。** 如果只做检查不记录，误杀率就永远算不出来，这个工具也就失去了它最大的用途。

## 输出时怎么说

**要做的：**

- 明确告诉用户三栏分别是什么，以及每一条的"他们做了什么 / 没做什么"
- 给出差异化假设："如果要做，差异点应该落在 X，因为 Y"
- 诚实标注风险：如果整个方向确实被做透了，直说，并建议转向

**不要做的：**

- 不要说"这个方向已经被人做过了"——这是二值结论，是被禁止的
- 不要为了让用户开心而缩小重合度
- 不要为了让工具显得有用而夸大重合度
- **不要用"看起来相关"当作"已被占据"的证据**

## 已知限制（实测得出，必须转告用户）

1. **arXiv / OpenAlex 对中文检索式几乎无效。** 两个源都以英文为主。要么让 LLM 生成英文检索式（默认），要么用 `--query` 手写。
2. **Semantic Scholar 免费额度会返回 429**，已优雅降级，不影响其他源。
3. **不接 LLM 时检索质量很差。** 纯关键词搜索噪声极大——LLM 的"拆解主张 + 三栏判定"是**必需步骤，不是可选优化**。
4. **判定有随机性。** 检索部分是确定性的（可记录、可复现），判定部分依赖 LLM。关键结论建议人工复核或换模型重跑一次。
5. **它不能替代读论文。** 工具能告诉你去读哪几篇，不能替你判断"是不是同一个东西"——历史上那次误杀，恰恰发生在这里。
6. **报告含未发表的想法，不要提交到公开仓库。** `reports/` 已在 `.gitignore` 里。
