## 2. 路线 A：过度澄清的度量、尺子与解法（⚠️ 已被撞车，见第 8 节）

### A.1 贡献声明（写作时直接改成一段话）

1. 我们给出**过度澄清（over-clarification）**的系统分类法，补上现有失败编目缺失的一侧；
2. 我们提出一个**无需人工标注即可大规模运行**的"提问必要性"自动指标；
3. 我们给出一个**在打扰预算约束下**的提问策略，并在准确率-交互成本 Pareto 前沿上超越固定阈值与纯 prompt 方法。

### A.2 三个假设

- **H1**：主流 agent 在交互式任务中存在系统性的冗余澄清；按"每次成功所需提问数"排序，模型间差异显著且**不可由参数规模预测**（依据：Act-or-Escalate 已证明升级阈值与规模无关，[arXiv:2604.08588](https://arxiv.org/abs/2604.08588)）。
- **H2**：遮蔽反馈的反事实信号，可以作为"这次提问是否必要"的**评测指标**（原先只被用作训练奖励，见 InfoPO [arXiv:2603.00656](https://arxiv.org/abs/2603.00656)），且与人工判断达到可接受一致性（判断：目标 Cohen's κ ≥ 0.6）。
- **H3**：在固定提问预算下，约束式策略的 Pareto 前沿严格优于固定置信度阈值与纯 prompt。

### A.3 步骤 1：构造评测集（对应贡献 1）

**为什么是空白**：MAST 的 14 个失败模式里有正式的 FM-2.2「Fail to Ask for Clarification」，但**没有任何"过度澄清"模式**——失败编目本身只惩罚一侧（来源：[arXiv:2503.13657](https://arxiv.org/abs/2503.13657)，版本敏感，引用需标版本）。

**数据来源（优先级从高到低）**：

1. **τ-bench**：`Tool-Agent-User Interaction` 基准，自带用户模拟器与多轮交互，适合做反馈重放（[arXiv:2406.12045](https://arxiv.org/abs/2406.12045)，CC BY 4.0）。
2. **BFCL 多轮子集**：伯克利函数调用排行榜，含多轮工具调用（[ICML 2025](https://icml.cc/virtual/2025/poster/46593)，[排行榜](https://gorilla.cs.berkeley.edu/leaderboard.html)）。
3. **NoisyToolBench**：Ask-when-Needed 论文构建的"指令不完整"工具调用基准，论文声明会公开代码与数据（[arXiv:2409.00557](https://arxiv.org/abs/2409.00557)）——**发布状态待核实，见第 6 节**。
4. **自建**：若上述不足以覆盖"冗余提问"，用同一套工具 schema 自行构造（方法是下面两个方向的对称构造）。

**构造方法：从两个方向对称地造**

- **正例（该问没问）**：删掉指令中的关键参数 → agent 若不问就只能猜。可直接复用 NoisyToolBench 的构造思路。
- **负例（不该问却问了）**：给出**信息完备**的指令，但故意加入"看似歧义"的表面特征（同义工具名、可推断的默认值、上下文中已给出的信息），记录 agent 是否仍然提问。**这是现有基准完全缺失的一侧。**

**规模建议（判断）**：400–800 条，其中正负例大致均衡；每条标注 `必要 / 可省 / 有害` 三档。

**标注规范（关键，直接决定审稿人信不信）**：

给标注员看四元组 `(对话上下文, agent 的提问, 用户的回答, 后续实际走向)`，只问一个问题：

> **如果省略这次提问，agent 能否做出同样正确的决定？**
> - 必要 = 不能，删掉就会做错
> - 可省 = 能，删掉结果一样
> - 有害 = 不但能，而且这次提问还导致后续偏差（如把用户带偏、引出错误偏好）

禁止让标注员评价"这个提问好不好"——那是态度题，不是判据题。

### A.4 步骤 2：自动化必要性指标（对应贡献 2）

**核心定义**：在第 t 轮，agent 发起提问 q，得到用户反馈 f。构造**反事实**：把 f 遮蔽（或替换为最小信息占位），让 agent 从第 t+1 步重新决策，比较动作分布。

- 动作分布**显著改变** → q 提供了信息 → 必要
- 动作分布**几乎不变** → q 冗余
- 分布改变但**朝错误方向** → 有害

**三个必须处理的技术坑**（这是这条路线真正的工程量所在）：

1. **遮蔽后 agent 会崩**：直接删除反馈常导致模型无法继续。解法是用**最小信息替代**（如 `"(用户未提供额外信息，请自行决定)"`），而不是留空。
2. **单次采样噪声大**：必须用 temperature > 0 采样 n = 8–16 次估计动作分布，用**动作一致率**或分布散度作为统计量，不能只看一次。
3. **阈值主观**：先在一小批数据上人工定阈值，再冻结，并报告阈值敏感性分析。

**与人工判断的一致性验证（100 人的正确用法）**：

- 从模型输出里抽样 **200 条**；每条 **3 名标注员**（共 600 次判断）
- 每人**只标 6–8 条**（避免疲劳），题序随机，标注任务直接做成一份 10 分钟问卷
- 报告 Cohen's κ / Fleiss' κ，目标 ≥ 0.6（参考：MAST 的专家标注 κ = 0.88，众包 0.6 是可接受线）
- **无论一致性高低都要写进论文**：低一致性本身就是发现（说明"必要性"这个概念本身模糊），并附分歧案例分析

### A.5 步骤 3：预算约束下的提问策略（对应贡献 3）

**问题形式化**：给定每任务提问上限 k，最大化任务成功率；等价于最大化 `成功率 − λ·提问数` 的拉格朗日形式，扫 λ 得到 Pareto 前沿。

**为什么是空白**：现有的 EVPI / VoI 方法（[ACL 2026](https://aclanthology.org/2026.acl-long.1987/)、[arXiv:2511.08798](https://arxiv.org/abs/2511.08798)）都是**无约束**的边际权衡，没有"预算是硬的"这一设定。（判断）

**三种实现（按你的算力条件排序）**：

1. **推理时（推荐，纯 API）**：每轮并行采样 K 条候选路径（问 / 不问），用反事实指标估计信息增益，在预算内贪心选择。代价是 token 数量上升，但完全不需要训练。
2. **约束解码 / 打分重排**：对"提问"这个动作加惩罚项，扫系数。
3. **训练式（可选扩展，需租云 GPU）**：参考 InfoPO 的信息增益奖励做 GRPO。**建议作为论文的第 4 个贡献或后续工作，不要让它成为主线依赖。**

**Baseline 清单（必须全部跑，否则会被质疑）**：

| Baseline | 说明 |
|---|---|
| Never-ask | 永不澄清，直接猜 |
| Always-ask | 每步都问（上界成本、下界效率） |
| 固定置信度阈值 | 自评置信度 < 阈值就问（现有主流做法） |
| 纯 prompt | "只在真正歧义时提问" |
| EVPI 无预算 | ACL 2026 思路的复现 |
| **你的方法** | 预算约束 |

### A.6 实验矩阵与评测口径

- **模型**：至少 4–6 个，跨厂商跨规模，**中文模型与英文模型都要有**（DeepSeek / Qwen / GLM / Kimi 与 GPT / Claude / Gemini 系列）。这样能顺带得出"中文模型提问倾向"的分析结果——**作为模型属性分析，不作为文化结论**。
- **指标**：
  - 任务成功率（Pass@1 / τ-bench 的 pass^k）
  - **平均提问数**
  - **每成功一次的提问数**（核心指标）
  - 用户操作数 / 交互轮数
  - **Pareto 超体积（HV）**——报告曲线，不要只报单点
- **消融**：反事实采样数 n、阈值、最小信息替代的措辞、预算 k 的扫描
- **可复现性**：固定随机种子、报告 API 版本与日期（模型会更新，这是审稿人会问的）

### A.7 论文骨架

1. Introduction：现有评测看不见"多问"；失败分类法缺一类
2. Related Work：澄清问题生成 / 延迟决策与 VoI / 交互式 agent 评测
3. Taxonomy：过度澄清的类型学（**这是最容易被说"常识罗列"的一节，要给出互斥且穷尽的定义**）
4. Benchmark 构建与统计
5. 反事实必要性指标 + 人工一致性
6. 预算约束方法
7. 实验：Pareto 前沿、消融、跨模型分析
8. 讨论与局限（尤其要写清"提问次数"不等于"用户真实成本"）

| 风险 | 预案 |

## 3. 路线 B：中文工具调用歧义基准

**贡献**：中文场景的歧义澄清基准（数据集论文）。

**为什么是空白**：AmbigQA、Qulac、ClarifyBench 全部是英文（Qulac [SIGIR 2019](https://doi.org/10.1145/3331184.3331265)；ClarifyBench 见 [arXiv:2511.08798](https://arxiv.org/abs/2511.08798)）。中文工具调用场景的歧义基准不存在。（判断）

**做法**：
1. 复用 NoisyToolBench 的构造方法，迁移到中文工具 schema（中文 API 文档、中文参数名、中文模糊表达）；
2. 歧义来源要分类覆盖：参数缺失 / 指代不明 / 量纲与单位 / 同名不同义的工具 / 上下文可推断但未明说；
3. 规模 500–1000 条；
4. **100 人的用法**：标注验证（判断"这条指令是否真的歧义"），不是被试。

**能被审稿人接受的关键**：与英文基准做**可对齐的子集**（同一批工具语义、同一批歧义类型），这样"中文基准"才不是孤岛。只做中文、不做对齐，容易被说成区域性工作。

**去向**：CCL / NLPCC 数据集 track 为现实选择，ACL/EMNLP 数据集 track 需要更大的规模和更强的对齐设计。

## 4. 路线 C：多智能体通信信息增益审计（练手篇）

**贡献**：对公开多智能体 trace 的通信效率做系统性测量。

**为什么是空白**：AAAI 2026 已经有人用**拍卖机制给 agent 间消息定价**（[链接](https://ojs.aaai.org/index.php/AAAI/article/view/40182)），但**没有人测量过真实 trace 里"零信息增益消息"占多少**。（判断）

**做法**：
1. 用公开的 MAST-Data（1600+ 条 trace，含 7 个主流框架）作为语料；
2. 定义信息增益代理指标（例如：该消息之后下一个 agent 的动作分布是否改变、是否引入了上下文中不存在的新信息）；
3. 报告：零增益消息占比、按框架/模型分组、以及"消息数 vs 任务成功"的关系。

**诚实定位**：这是**测量类工作**，天花板在 workshop/findings，主要价值是练手 + 建立你的实验管线，**不要当主线**。优点是 1–2 周就能出版型。

## 5. 一周内可以做的第一步

不管最后选哪条，下面三件事都值得先做，而且一周内能完成：

1. **跑通一个交互式 harness**：把 τ-bench 的多轮交互跑起来，确认你能记录"第几轮、问了什么、用户答了什么、后续做了什么"。**没有这个日志格式，后面所有分析都做不了。**
2. **做一次快速测量**：让 3 个模型在同一个数据集上跑，只统计一个数——**每成功一次的提问数**。如果模型间差异明显，路线 A 的 H1 就有苗头；如果几乎没差异，及早换方向。
3. **试 50 条反事实**：手工构造 50 次"遮蔽反馈"的重放，先看这个判定到底稳不稳。这一步的结论会直接决定路线 A 是 3 个月还是 3 周。

## 7. 一句话选择建议

- **想在计算机方向立住 → 走路线 A。** 它的结构与 CS 会议的标准论文完全对齐（分类法 + 数据集 + 指标 + 方法），而且**即使方法部分失败，论文仍然成立**（见 A.9 预案）——这一点对第一次做研究的人很重要。
- **想快点有产出 → 走路线 C。** 一到两周出版型，用来验证你的实验管线和写作流程。
- **想最大化你的中文优势 → 路线 B**，但必须做英文对齐子集，否则会被当成区域性工作。

## 8. 撞车检查结果（2026-10-10）与转向建议

### 8.1 路线 A 三个组件全部被命中

| 本方案的组件 | 撞车论文 | 日期 | 撞车程度 |
|---|---|---|---|
| **C2 反事实必要性指标** | [CONTRA: Discovering and Qualifying Behavior-Changing Questions for Selective Clarification in LLM Code Generation](https://arxiv.org/abs/2610.01769) | 2026-10-01 | **技术核心相同。** 原文做法："为每个候选问题生成两个可能答案下的程序，检查在共享输入上是否存在**稳定行为差异**"——这就是本方案 A.4 的"遮蔽反馈、看动作分布是否改变"。他们命名为 behavior-changing questions，已开源并做成 Claude Code 插件 |
| **C3 预算约束策略 + Pareto** | [Pareto-Dominant Clarification: Post-Training Coding LLMs via PPO-Lagrangian Budget Constraints](https://arxiv.org/abs/2610.04089)（EMNLP 2026 LMP Workshop） | 2026-10-02 | **几乎逐字重复。** 同样把澄清建模成 CMDP + 期望提问预算约束，同样报 Pareto 前沿，同样得出"未受约束的澄清行为是 Pareto 无效的"。本方案 A.5 的 H3 与他们的主结论重合 |
| **C1 过度澄清评测基准** | [ClarifyCodeBench](https://arxiv.org/abs/2607.00711)、[Clarify-Then-Search](https://arxiv.org/abs/2608.20357)、[CLAMBER](https://arxiv.org/abs/2405.12063)、[ClarQ-LLM](https://arxiv.org/abs/2409.06097)、[HumanEvalComm](https://dl.acm.org/doi/10.1145/3715109)、ClarifyBench | 2024–2026 | 基准赛道已拥挤。且 F1 类指标本身已隐含惩罚多余提问（多余问题计为 false positive），"没人惩罚多问"这个立论已被削弱 |
| **H1「模型系统性过度提问」** | [Ask Early, Ask Late, Ask Right: When Does Clarification Timing Matter for Long-Horizon Agents?](https://arxiv.org/abs/2605.07937) | 2026-05 | **已发表并给了数字**：300 个未脚本化会话中 **52% 过度提问**，并称"没有前沿模型在经验最优窗口内提问" |

**结论：路线 A 的核心贡献、方法与动机叙述都已被占，不能按原样执行。**

### 8.2 仍然空白的部分（精确版）

**① 成本侧仍然是假设值——这是最大的、也最贴合原始问题的空白。**

- Ask Early / Ask Late 填的是**价值侧**（澄清在轨迹哪个位置值多少），并自称"提供了现有理论框架所缺的定量基础"；
- 但**成本侧**（问一次让用户付出多少）在所有工作中仍是**假设的常数**：
  - Pareto 那篇用 **GPT-4o-mini oracle simulator** 当用户，成本是"提问次数"；
  - Ask Early / Ask Late 用**强制执行（forced injection）**，不是真实用户反应；
  - CONTRA 用基准标注，成本同样抽象为计数。
- **没有人用真实人类的成本数据校准过这一项，也没有人证明换掉成本项后策略排序会变。**

→ 这正是你 100 人和内部数据的用武之地，而且它直接回答你最开始的问题（"AI 不懂社交成本吗"）。

**② 中文轴未被覆盖。** CLAMBER / ClarQ-LLM / ClarifyCodeBench / Clarify-Then-Search / HumanEvalComm **全部是英文**，检索未发现中文澄清基准。但只做"中文版"会被判为翻译工作，必须附带英文基准没有的**结构性差异**（中文歧义来源分布：省略主语、量词与单位、高语境省略指令）。

**③ 统一评测 / 复现研究。** 现存方法（CONTRA、Pareto-CMDP、SAGE-Agent、AwN、EVPI、置信度阈值、纯 prompt）**各自的成本定义不一致**（提问次数？token？轮数？），结论不可比。在统一 harness 下复现与排序，门槛低、必然有结果，而且领域刚变热正需要这种工作。

### 8.3 转向后的推荐路线

**新路线 A′：成本侧校准 + 统一评测（两者拼成一篇）**

| 阶段 | 内容 | 风险 |
|---|---|---|
| 阶段 1 | 搭统一 harness，复现 6 个现存方法（CONTRA / Pareto-CMDP / SAGE-Agent / AwN / 阈值 / prompt），**报告各家成本定义不一致导致的排序差异** | 极低，必然有结果 |
| 阶段 2 | 用真人数据（100 人 + 内部日志）替换成本项，**证明换掉成本项后策略排序会翻转** | 中，但不影响阶段 1 单独成立 |

- 阶段 1 单独就是一篇合格的评测类论文（EMNLP/ACL findings 或 workshop）；
- 阶段 2 是真正的新贡献，且依赖你独有的资源；
- **整体叙事**：所有人都在优化"何时问"，但代价函数是猜的；我们测出真实的代价函数，并证明这改变了最优策略。

**备选：路线 B 作为保底**（中文基准 + 中文歧义类型学），天花板较低但确定性高。

### 8.4 时效性警告

两篇致命撞车论文分别出现在 **2026-10-01 和 2026-10-02**——距今 9 天。这说明该方向正处于爆发期：

- **不要做大而全的"我从头建一个基准"**，会被持续追尾；
- **要做依赖独有资源的东西**（真人成本数据、中文场景、内部日志），这类资产别人短期抄不走；
- **两周内先验证**：把统一 harness 搭起来，看阶段 2 的成本数据有没有故事，再决定是否投入。
