# 想法日志（Idea Log）

> **唯一目的：测量"撞车检查"的误杀率。**
>
> 为什么必须现在开始：**被放弃的想法不留任何痕迹，事后无法重建。** 这份表从你填第一行的那天开始产生数据，之前的一切都补不回来。
>
> 复制这个文件到你的私有位置（建议命名为 `idea-log.local.md`，已在 `.gitignore` 里），然后开始填。

---

## 一、记录规则（三条，别加）

1. **每个"认真考虑过"的想法都记一行。** 标准很低：只要为它花过半小时以上，或者让它跑过一次撞车检查，就记。
2. **决定当天记，不要事后补。** 事后补会无意识美化——尤其是"放弃"的理由。
3. **写"当时怎么想的"，不写"现在觉得对不对"。** 这份数据的价值在于它是**决策时点**的快照。

---

## 二、字段定义

| 字段 | 填什么 | 注意 |
|---|---|---|
| `编号` | IL-001 递增 | |
| `日期` | YYYY-MM-DD | 产生想法或做撞车检查的日期 |
| `想法一句话` | 一句话说清做什么 | 不要写成摘要，写你脑子里那句话 |
| `类型` | 方法 / 评测 / 数据集 / 应用 / 元研究 | |
| `撞车检查方式` | 工具、检索式、时间窗 | **必须写清**，否则无法比较不同检查的严格程度 |
| `检查结论` | `真撞车` / `看起来像` / `没查到` | 三选一，判据见下 |
| `当时的情绪` | 一句话 | 看起来很软，但它可能是最强的预测变量 |
| `决定` | `继续` / `修改` / `放弃` | |
| `回访日期` | 决定日 + 90 天 | 填表时就把日期算出来写上 |
| `回访结论` | 90 天后填：**这条想法实际有人做了吗？** | **最关键的一列** |
| `备注` | 补充 | |

### 判定判据（必须严格遵守）

| 结论 | 判据 |
|---|---|
| **真撞车** | 我**读了对方的方法部分**，确认核心做法与我一致 |
| **看起来像** | **只看了标题或摘要**，标题/关键词高度重合但没核实方法 |
| **没查到** | 检索过了，没找到相关的工作 |

⚠️ 这一列是核心测量。**一开始你一定会想把"看起来像"归到"真撞车"里。不要。**
分清这两者的困难程度，本身就是研究结果的一部分。

## 四、90 天后怎么算

**1. 误杀率（最重要）**

```
误杀率 = 回访发现"其实没人做"的想法数 / 当时判定为撞车的想法数
```

分子只看"当时决定放弃或大改"的那些。一个想法当时判了撞车、放弃了，90 天后发现根本没人做——**这次放弃就是误杀**。

**2. 检查严格度 vs 放弃率**

把 `撞车检查方式` 按严格度排序（粗略三档：只搜标题 / 搜摘要 / 读方法），看放弃率怎么变。

**3. 情绪与放弃的关系**

`当时的情绪` 里出现"烦""算了""不想看了"的行，放弃率是否显著高于其他行。

---

## 五、什么时候升级成正式研究

**触发条件（满足任意一条）：**

- 记录满 **20 行**，且其中判定为撞车的 ≥ 8 行；
- 出现 **≥ 3 次**"判了撞车 → 放弃 → 90 天后发现没人做"；
- 你自己发现了某个模式，想验证它是不是普遍现象。

**升级方式：** 变成 N 人前瞻性队列——招募研究者，每人提交若干想法，**随机分配**"严格报告 / 宽松报告 / 无报告"三种条件，测放弃率差异。

**那份 n=1 的日志就是预实验数据**：证明设计可行、指标可测、效应存在。没有它，直接上大队列是盲的。

---

## 六、归档

- 每次填完存一份带日期的副本（如 `idea-log-20261110.md`），避免误删；
- 要分析时把它们转成 CSV，或直接算上面三个指标；
- **不要提交到公开仓库。** 它记录的是你尚未公开的想法。
